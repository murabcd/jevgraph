# Canvas

The canvas edits the chatflow that runs on each message and highlights only the current turn's reached path. Outputs and timing details also belong to that turn. Chat remains the only runner. See [[routing]] and [[chat]].

## Graph and editors

The graph compiler and editor own the visible node connections and settings.

[src/flow/graph.ts](../src/flow/graph.ts) owns connection rules, graph compilation, and local persistence. [src/flow/use-routing-graph.ts](../src/flow/use-routing-graph.ts) owns edits. [src/flow/routing-canvas.tsx](../src/flow/routing-canvas.tsx) renders the React Flow graph while [src/flow/canvas-presentation.ts](../src/flow/canvas-presentation.ts) derives the visible nodes, edges, and latest-turn highlights. [src/flow/route-node.tsx](../src/flow/route-node.tsx) renders node actions and execution state, and [src/flow/node-meta.ts](../src/flow/node-meta.ts) owns display names and footer summaries. [src/flow/canvas-controls.tsx](../src/flow/canvas-controls.tsx) renders the canvas toolbar. [src/flow/route-node-panel.tsx](../src/flow/route-node-panel.tsx) renders one editor or inspection Sheet for the selected node outside the React Flow nodes.

Start is the single required root. Its [editor](../src/flow/start-editor.tsx) defines typed input fields and optional defaults. The chat message is the built-in query input. Jev and Model editors use [Start variable binding](../src/flow/start-variable-binding.tsx) to select only the custom fields they need. Jev evaluates its configured Choice, Noul, or Score question; its editor sets a minimum provider confidence for Choice and Score or a minimum selected-answer probability for Noul, plus an explicit output for results below the threshold or failed evaluations. Its node and editor title is Jev, the provider name; its role badge reads Classifier for Choice and Router for the other types. Model calls OpenAI or Gemini and can have its own System instructions, ordered User and Assistant example messages, output token limit, supported reasoning effort, several Continue connections, and one backup Model. The latest chat message is sent to a reached Model automatically. A Model's two output rows label the regular path Continue and the failure path On error. Once On error has a backup connection, its handle cannot start another connection; removing that edge makes the handle available again. A backup Model is a leaf and shows no outgoing handles. Clicking a node opens its settings in a floating, nonmodal Sheet on the left. The Sheet has no backdrop, so the canvas remains visible and interactive; clicking another node switches the editor. [src/flow/prompt-editor.tsx](../src/flow/prompt-editor.tsx) owns the Model form, [src/flow/model-thinking-field.tsx](../src/flow/model-thinking-field.tsx) owns its model-specific thinking control, and [src/flow/model-messages-editor.tsx](../src/flow/model-messages-editor.tsx) renders its role-based messages. [src/flow/jev-question-editor.tsx](../src/flow/jev-question-editor.tsx) owns the Jev form, and [src/components/ui/sheet.tsx](../src/components/ui/sheet.tsx) owns the floating variant.

The toolbar offers Classifier or Model; Classifier creates the same Jev node with Choice selected by default. Dragging a loose output opens [src/flow/node-connection-picker.tsx](../src/flow/node-connection-picker.tsx) with compatible types. Start can launch several parallel branches and cannot be removed. A Jev output can connect onward or remain unconnected to return its label in chat. A Jev output connected back to an earlier Model becomes a dashed Repeat edge; the Jev editor exposes its repeat limit. A repeat still needs a connected non-repeat exit. Forward edges cannot cycle. An incomplete graph persists but chat cannot send it.

The initial canvas contains Start connected to an unconfigured Jev node. New Jev questions have blank instructions and answer criteria. Choice shows Choice 1 and Choice 2, Noul shows Yes and No, and Score shows numbered levels. These are structural labels, not routing policies. Users complete the question in the editor before the graph can run. The graph storage key is `router:graph:v3`; older example graphs are not loaded.

The floating editors use [src/components/ui/select.tsx](../src/components/ui/select.tsx) for Jev question type, uncertain-result output, repeat limit, model selection, and supported reasoning effort. The [model catalog](../src/lib/models.ts) defines each model's available levels and initial selection. The picker contains only GPT-6 Luna (`gpt-6-luna`) and Gemini 3.8 Flash (`gemini-3.8-flash`), both initially at Medium reasoning. Luna supports None, Low, Medium, High, Xhigh, and Max; Gemini supports Low, Medium, and High. Removed models cannot run through the API; existing canvas nodes can be reconfigured without losing their connections. The question type menu uses the Jev icon for each option; all menus have an inset around their options and follow the app theme. The editor saves each node's settings together; Cancel discards the draft. Choice and Score output IDs preserve their edges when labels change. Changing question type removes that Jev node's outgoing connections; users connect the new outputs explicitly.

Start field names and their smaller type labels share a text baseline. [src/flow/selection-row.tsx](../src/flow/selection-row.tsx) supplies the common bordered, left-aligned selection row for Start variable bindings, earlier results, relevance, and custom rates. A selected row keeps its padding and border, gains a background, and shows a checkmark at the right. Context menus use the same SelectGroup inset as the existing editor selects; their options include icons.

Model duplication uses the same configuration projection as graph persistence, retaining prompt messages, variables, context, rates, output limits, and reasoning effort. It starts with empty execution state and no connections. Reasoning has one effort value for the current catalog; unsupported numeric budgets have no editor, persisted field, or API execution path.

## Observation and persistence

Starting a message clears the previous path immediately. Progress events highlight reached nodes, traversed edges, and their output handles for that message. The path, timings, and node details remain visible after its answer but are not persisted.

Start also edits reference documents through [src/flow/context-documents-editor.tsx](../src/flow/context-documents-editor.tsx). Jev and Model editors share [src/flow/context-policy-fields.tsx](../src/flow/context-policy-fields.tsx) for history, stage-result bindings, document full/summary/omit settings, optional relevance, and optional-context budgets. [src/flow/pricing-fields.tsx](../src/flow/pricing-fields.tsx) shows automatic published rates and edits optional overrides; changing a Model clears rates belonging to the previous model. Removing a source document or node removes its bindings. [src/flow/node-run-details.tsx](../src/flow/node-run-details.tsx) inspects provider attempts, structured decisions, and included/omitted context excerpts for the current turn. See [[context]].

Clearing chat removes the highlight; changing the graph hides a trace recorded for a different configuration.

Node badges show connection order and role; the Start footer shows only Input. Every node footer has the same fixed height even when the node body grows to show more outputs or connections. Node cards leave their handle circles visible past the card edge. A selected node has a neutral ring; selection does not color its unused outputs as executed. Unused branches, including a backup that did not run, remain unhighlighted. The top-right time starts on each provider start event and updates every 100 ms while that node runs, using tabular numerals, milliseconds below one second and seconds afterward. [src/flow/node-timer-label.tsx](../src/flow/node-timer-label.tsx) updates only its label, so clock ticks do not rerender the canvas graph. Completion replaces the live estimate with server-measured time; failures stay red and stream interruption freezes unfinished timers. Repeated runs and relevance calls show cumulative time and count; parallel nodes keep independent clocks. Clicking a node edits it; other nodes' options menu can inspect the latest output or decision, focus, duplicate a Model, or remove the node. Failed attempts retain their error-colored time. These observations are not saved with the graph.

The graph and node positions persist locally. [src/flow/canvas-viewport.ts](../src/flow/canvas-viewport.ts) persists pan and zoom separately; refresh restores the saved viewport, and Fit saves a new one. Opening a node editor leaves the canvas pan and zoom unchanged. The floating chat panel opens without resizing the canvas.

Model settings optionally enable expected-cost routing and select acceptable models with the same bordered checkmark rows as variable bindings. Common reasoning levels are the intersection of selected candidates. Automatic nodes display Auto with the Shuffle icon and an Automatic footer before execution, then the actual chosen model for that turn. Automatic context selects document bindings using checked rows and hides the separate relevance option. [[optimization]] owns the detailed planning contract. Duplication, graph compilation, and persistence include both policies; inspection adds candidate forecasts and preparation costs without persisting the trace.
