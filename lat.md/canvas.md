# Canvas

The canvas routes each chat message directly to a Model or through ordinary Jev nodes. A System node can add reusable instructions before routing, but the chat composer supplies the message even when System is absent. See [[routing]] and [[chat]].

## Graph and interaction

[src/flow/graph.ts](../src/flow/graph.ts) defines graph structure, route conversion, and persistence. [src/flow/use-routing-graph.ts](../src/flow/use-routing-graph.ts) owns canvas state and edits.

Each Jev output can lead to another Jev node or a Model, and a Model can connect one backup Model.

[src/flow/routing-canvas.tsx](../src/flow/routing-canvas.tsx) renders the flow; [src/flow/route-node.tsx](../src/flow/route-node.tsx) renders nodes and their action menus. [src/flow/system-prompt-editor.tsx](../src/flow/system-prompt-editor.tsx) and [src/flow/jev-question-editor.tsx](../src/flow/jev-question-editor.tsx) own the System and Router settings Sheets. [src/flow/jev-question-picker.tsx](../src/flow/jev-question-picker.tsx) owns the Router toolbar's question type picker. [src/flow/model-picker.tsx](../src/flow/model-picker.tsx) and [src/flow/model-command.tsx](../src/flow/model-command.tsx) provide the model toolbar and searchable model list, while [src/flow/node-connection-picker.tsx](../src/flow/node-connection-picker.tsx) displays the available node types at a loose connection endpoint.

Node badges use unique numbers in connection order. Connected terminal Model nodes are labeled OUTPUT; unconnected Model nodes retain MODEL. The Model picker and node footer identify the provider model regardless of that badge.

After a node runs, its elapsed time appears as plain text at the top right with tabular numerals, in milliseconds below one second and seconds afterward. Nodes without a timing event show nothing. A failed node keeps its elapsed attempt time in the error color. Timings belong to the latest run of the current graph and are not persisted. See [[routing]] for measurement boundaries.

The Jev footer displays its current question type as metadata. Every configured output appears as a labeled row inside the node with its handle beside the label, including unconnected outputs. The node grows as outputs are added. The selected Router toolbar exposes a searchable Choice, Noul, or Score picker beside the node menu. Choosing a type updates the graph immediately. Edit in the node menu opens a right-side Sheet with instructions and fields for the current question type. The Score editor and node show the same numbered levels, with one handle per level. Save applies the question and its output handles, while Cancel discards the draft. Choice and Score edits preserve connections by stable output ID; removing an output removes its edge. Changing types maps lower outputs to the simpler model and upper outputs to the deeper model.

The System node stays compact and shows a summary of its reusable prompt in the footer. Edit in its menu opens a Sheet with a multiline prompt field. Save stores the prompt in the graph; Cancel discards the edit. The prompt is independent of the [[chat]] composer and is sent as instructions with each chat turn. Selected Model nodes show a searchable provider model picker in the toolbar beneath the node; choosing a model applies it immediately.

Every node, including System and Jev, can be removed. The Add node control in the bottom toolbar opens a searchable list of available node types: System appears only when absent, while Router and Model can be added repeatedly. Removing System promotes its connected next node to the saved entry point; a graph created without System uses its sole root node. An empty or incomplete workflow persists across refresh. Chat runs when the entry reaches a Model and every reachable Jev output reaches a Model without a cycle.

Dragging from System into empty space opens a temporary picker offering Model or Router. Dragging from a Jev output offers another Router or Model; dragging from a Model's fallback handle offers a Model. Choosing a type creates a connected, selected node at the drop point. A new direct Model starts with OpenAI; new Jev branch models use the branch's default model. Selected System and Router nodes expose Edit Sheets through their menus; selected Model nodes expose a model picker in their toolbar. Escape or clicking outside dismisses the connection picker without changing the saved graph. Connecting to an existing compatible node changes that connection directly. The graph and node positions persist locally; temporary pickers and preview edges do not.

The bottom-left toolbar controls the canvas. A matching bottom-right button toggles the floating [[chat]] above the canvas without changing the graph viewport. [src/flow/canvas-viewport.ts](../src/flow/canvas-viewport.ts) validates and persists pan position and zoom separately from the graph. On refresh, the saved viewport is restored; the initial fit runs only when no valid viewport exists. The Fit canvas control sets and saves a new view.
