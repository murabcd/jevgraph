# Routing

One workflow graph runs for each chat turn. The server calls models, evaluates Jev questions, joins parallel results, repeats a bounded branch, and returns one final answer from a Model or Jev. See [[canvas]] and [[chat]].

## Execution contract

The workflow schema describes connected forward stages and bounded Jev feedback edges.

[src/lib/routing.ts](../src/lib/routing.ts) validates the authenticated request's conversation ID and request UUID, single workflow route shape, and Start input schema. Old session-ID requests and requests without persistence identity are rejected. The graph has one explicit Start, followed by Jev and Model nodes. Start holds typed fields; request metadata must match declared field names and types, while defaults fill omitted values. Each Jev or Model selects which fields it receives. Forward edges form an acyclic graph; a Jev output may have one explicit repeat edge to an upstream Model. A Model can have several Continue edges for parallel work and one explicit backup Model. A Jev output has at most one target; an unconnected output ends the path with its selected label.

[server/workflow.ts](../server/workflow.ts) evaluates only reached nodes. It runs up to four independent nodes concurrently, waits for reachable upstream work to finish before running a join, and carries the newest output of each upstream node forward. This wait also covers a branch that repeats before joining. Model results can feed later Jev evaluations or Model prompts. Intermediate model text is buffered; a terminal Model streams directly to chat. When Jev selects an unconnected output above the configured threshold, its label goes to chat without a Model call. A configured fallback output can also return its label directly. Multiple unjoined final results are an error.

A Jev repeat edge reruns its upstream Model and following stages. The Jev node's repeat limit is configurable from one to five, with three as the default. If Jev still chooses repeat after that limit, execution stops with `repeat-exhausted`, retains the original selected branch and latest draft, and reports that review did not pass. It never traverses the non-repeat exit or runs its downstream model. A turn also has a 20-pass, 100-node-operation, 200-provider-attempt, and two-minute budget.

Model execution receives one `WorkflowModelRequest` owned by [server/workflow.ts](../server/workflow.ts): the target, selected Start variables, prepared context, and delta callback. The API consumes the selected inputs from that context instead of accepting a second upstream-output array that could disagree with it. The relevance callback's model and usage fields belong to its `RelevanceResult` contract in [server/context.ts](../server/context.ts).

## Jev and provider calls

Jev evaluates decisions; OpenAI and Gemini generate prose through direct providers.

[server/api.ts](../server/api.ts) calls Jev through the TypeSafe AI SDK provider and experimental_evaluate, and calls OpenAI or Gemini through their direct AI SDK packages. Jev supports Choice, Noul, and Score evaluations; the installed Jev provider does not generate prose. [src/lib/jev-question.ts](../src/lib/jev-question.ts) owns question validation, answer resolution, and stable output IDs. Choice has editable named answers, Noul has Yes and No, and Score has one output per configured level. Blank question drafts can be saved in Convex but are rejected by the workflow schema until instructions and all answer criteria are filled in; the server never evaluates a placeholder question.

Each reached Jev node sees recent conversation messages, only its selected Start variables, and upstream results. For Choice and Score, its editor sets minimum provider confidence; for Noul, it sets the minimum probability of the chosen Yes or No answer, calculated as max(P(Yes), P(No)). Both use 70% by default. The editor also selects the output to take when the value is below the threshold or the provider fails. Without an explicit fallback output, an unreliable or failed evaluation reports an error. Request cancellation stops the turn. These thresholds are application policy, not accuracy claims. Every reached Model receives conversation history, its own optional System instructions, ordered User and Assistant example messages, selected Start variables, and upstream results. [server/model-prompt.ts](../server/model-prompt.ts) sends System instructions through the AI SDK `instructions` option, places example messages before conversation history, and includes Start values and upstream results as data with the latest live User message. [server/upstream-context.ts](../server/upstream-context.ts) formats prior node outputs for both Model and Jev calls. The editor sets maximum output tokens (1,400 by default) and model-specific thinking controls. [src/lib/models.ts](../src/lib/models.ts) owns the available settings: GPT-6 Luna and Gemini 3.8 Flash both start at Medium effort. Luna supports None, Low, Medium, High, Xhigh, and Max; Gemini supports Low, Medium, and High. The server passes supported efforts through the AI SDK `reasoning` option, except Luna Max, which uses the installed OpenAI provider's typed `reasoningEffort` option because the shared SDK reasoning enum lacks Max. Removed models and unsupported reasoning settings are rejected before provider calls. The server does not add an implicit assistant prompt.

## Provider failures

Model failover is one explicit backup attempt.

A connected backup is an alternative result for its primary stage and does not count as another final path. Model-only workflows can use a backup; independent terminal model branches must still join before producing one final answer.

[server/model-failover.ts](../server/model-failover.ts) tries a connected backup Model once when the primary fails before producing text. The backup connection alone enables this behavior. It never retries after a partial stream or after request cancellation. This is an intentional runtime failure policy, not a compatibility path.

## Stream and observation

The API streams progress, text, timings, and the final route to chat and canvas.

The API streams newline-delimited JSON parsed by [src/lib/route-stream.ts](../src/lib/route-stream.ts). Events report progress, route selection, per-node timing, text deltas, completion, and error. Progress includes reached nodes, traversed edges, Jev decisions, and bounded output previews. Node timing sums its provider calls, including relevance evaluations and repeat executions. Start reports zero milliseconds because it makes no provider call; unreached nodes have no timing. Request cancellation and a two-minute server deadline abort provider work.

Stream events are validated once against the source-owned schemas in [src/lib/routing.ts](../src/lib/routing.ts). Structured decisions retain the chosen routing branch, original Jev answer, value, probabilities, confidence, and accepted/uncertain/provider-error/exhausted status. Node outputs carry a producing node, logical stage, and revision. Context is built per attempt through [[context]]; Jev no longer applies its own hidden history window. Generation has zero implicit SDK retries so each recorded attempt corresponds to one provider request, while explicit failover still makes one backup attempt.

Each measured provider operation emits a `node-start` event before calling the provider, followed by a `timing` event with the server-measured completed or failed duration. [server/node-timing.ts](../server/node-timing.ts) owns this pair for generation, Jev decisions, and relevance; Start emits an immediate completed zero duration. [src/lib/node-timer.ts](../src/lib/node-timer.ts) tracks browser receipt time with a monotonic clock, sums settled attempt durations, and freezes unfinished timers as Interrupted when the stream ends. Client elapsed time never replaces or adds to the final server duration.

## Workflow usage

The workflow accounts for every attempted generation, summary, decision, and context relevance evaluation, including intermediate results, repeats, and failed backups.

[src/lib/usage.ts](../src/lib/usage.ts) owns per-call records, workflow aggregation, and optional USD estimates. Each call records its purpose, provider/model, duration, completion status, reported input/output tokens, any reported cached read/write and reasoning tokens, and error. [server/provider-usage.ts](../server/provider-usage.ts) normalizes installed SDK usage and preserves reported usage when a response later fails. Missing usage remains unknown, never zero. Progress exposes failed-call records even when the workflow cannot finish. Final usage sums all reported calls and marks incomplete totals when any input/output report is missing. Reasoning tokens remain a detail within output tokens and are not added twice.

Jev decision and relevance calls default to the [published TypeSafe price](https://docs.typesafe.ai/models), verified September 28, 2026: $0.042 per million input tokens and free output for `jev-1.13.0` and its current `jev-latest`/`jev-preview` aliases. [src/lib/model-pricing.ts](../src/lib/model-pricing.ts) owns provider-scoped prices, sources, and verification dates. The ledger records the returned Jev version when available; an unknown version has no default price. Each Jev or Model can override rates per million input/output tokens, with optional cache read/write rates; relevance evaluation has its own override. OpenAI and Gemini estimates default to Standard paid API pricing verified September 29, 2026: `gpt-6-luna` costs $0.10 input, $0.01 cached input, $0.125 cache writes, and $0.50 output per million tokens. Above 272,000 total input tokens, the entire call costs $0.20 input, $0.02 cached input, $0.25 cache writes, and $0.75 output. `gemini-3.8-flash` costs $0.75 input, $0.075 cached input, and $3.75 output through December 31, 2026; the catalog automatically applies $1.50/$0.15/$7.50 from January 1, 2027 UTC. Each attempt uses its own reported model and input count, including intermediate, repeated, backup, and failed calls with reported usage. Unknown versions or providers have no guessed rate. Editors show the selected model's current published rate and source alongside Custom rates; a supplied override takes precedence over all published tiers and schedules, and clearing it restores automatic pricing.

Estimates use API-reported token quantities, rather than character counts, and retain up to eight decimal places in the UI so small Jev costs stay visible. They use reported cache quantities and treat unspecified cache quantities as zero; provider bills and unreported cache details remain outside this estimate. If reported cache quantities need an unspecified rate, that call's estimate is unavailable. Aggregate costs are marked partial when any call lacks a usable estimate. Chat shows total calls, reported usage, and cost availability; node inspection shows the full call ledger. No savings or answer-quality claim follows from these measurements alone.

Optional Model routing evaluates the configured model or resolves a candidate using reviewed quality, full-turn latency and complete-route economics in [[optimization]]. Eligibility is checked before paid node context work and final generation prices are quoted after [[context]] preparation. Progress and final traces contain validated modelPlans with the candidate forecasts for each attempt. Summary and adequacy calls emit normal start/completion timings and ledger records, and shared summary reuse makes no extra provider call. Explicit backup execution retains its own context and routing policy.
