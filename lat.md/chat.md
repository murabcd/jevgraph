# Chat

Chat is a continuing conversation. Each sent message runs the current graph once, and the canvas observes that turn's execution. There is no separate workflow-run button. See [[routing]] and [[canvas]].

Chat submits up to 28 previous messages and the latest query; each node then selects its own history and sources through [[context]]. [src/chat/workflow-usage.tsx](../src/chat/workflow-usage.tsx) displays complete workflow call counts, reported token totals, optional estimated costs, and incomplete accounting labels. A `repeat-exhausted` response displays Review incomplete and never represents an approved answer. Graph configuration and completed turn measurements persist through [[persistence]].

The composer supplies the latest user message and recent history to Start. Start owns custom typed fields. Defaults support local chat testing; API clients can supply values for declared fields, and each downstream node receives only the fields it selects. Each Model's System instructions and optional example messages apply only to that node. The latest chat text is always sent as its live User message. A turn can route through Jev, call several models in parallel or sequence, repeat a bounded branch, and end at a Model or an unconnected Jev output. In the latter case chat receives the selected label. The chat UI sends no hardcoded business metadata.

[src/chat/use-route-chat.ts](../src/chat/use-route-chat.ts) owns optimistic messages, the request lifecycle, and the current stream's trace and timers. [[src/chat/use-saved-conversation.ts]] subscribes to saved messages and restores the latest full trace. Provider start events begin monotonic browser timers; completion events settle them with server durations. Ending an incomplete stream freezes active timers as Interrupted, while a new turn or changing conversation removes them. [src/chat/chat-panel.tsx](../src/chat/chat-panel.tsx) renders the floating chat and composer. [src/chat/chat-message-item.tsx](../src/chat/chat-message-item.tsx) renders turns, shows Shimmer-animated `Thinking` while waiting for answer text, and shows a Jev failure indicator when needed. [src/lib/route-stream.ts](../src/lib/route-stream.ts) decodes newline-delimited server events.

The composer starts compact, grows as text is entered, and scrolls after its maximum height. It remains editable while a response streams. Starting a new message clears the previous path, while older answers remain in chat. Closing chat retains the conversation and current path; New conversation starts a fresh chat while retaining the earlier transcript; the History menu reopens the most recent fifty conversations. Reload restores the current conversation. Graph edits hide traces recorded for another configuration. Chat panel visibility persists in browser local storage. Clicking the canvas keeps chat open; the explicit close control and launcher toggle hide it. When a floating node editor is also open, the editor stays left and chat stays right on wide screens; on narrow screens, chat stacks below the editor.

The durable conversation ID scopes temporary server cache evidence. Starting another conversation changes that scope; reload keeps it. Run creation precedes provider execution and records a unique request UUID, so duplicate requests never call providers twice. Other tabs observe the running lock and settled messages; streamed deltas remain local to the submitting tab. See [[persistence]].
