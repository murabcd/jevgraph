# Chat

Chat is a continuing conversation. Each sent message runs the current graph once, and the canvas observes that turn's execution. There is no separate workflow-run button. See [[routing]] and [[canvas]].

Chat submits up to 28 previous messages and the latest query; each node then selects its own history and sources through [[context]]. [src/chat/workflow-usage.tsx](../src/chat/workflow-usage.tsx) displays complete workflow call counts, reported token totals, optional estimated costs, and incomplete accounting labels. A `repeat-exhausted` response displays Review incomplete and never represents an approved answer. Graph configuration persists, while these turn-level measurements remain in memory.

The composer supplies the latest user message and recent history to Start. Start owns custom typed fields. Defaults support local chat testing; API clients can supply values for declared fields, and each downstream node receives only the fields it selects. Each Model's System instructions and optional example messages apply only to that node. The latest chat text is always sent as its live User message. A turn can route through Jev, call several models in parallel or sequence, repeat a bounded branch, and end at a Model or an unconnected Jev output. In the latter case chat receives the selected label. The chat UI sends no hardcoded business metadata.

[src/chat/use-route-chat.ts](../src/chat/use-route-chat.ts) owns in-memory messages, the request lifecycle, and the current turn's trace and timers. Provider start events begin monotonic browser timers; completion events settle them with server durations. Ending an incomplete stream freezes active timers as Interrupted, while a new turn or clearing chat removes them. [src/chat/chat-panel.tsx](../src/chat/chat-panel.tsx) renders the floating chat and composer. [src/chat/chat-message-item.tsx](../src/chat/chat-message-item.tsx) renders turns, shows Shimmer-animated `Thinking` while waiting for answer text, and shows a Jev failure indicator when needed. [src/lib/route-stream.ts](../src/lib/route-stream.ts) decodes newline-delimited server events.

The composer starts compact, grows as text is entered, and scrolls after its maximum height. It remains editable while a response streams. Starting a new message clears the previous path, while older answers remain in chat. Closing chat retains the conversation and current path; clearing it or reloading the page starts a new one. Graph edits hide traces recorded for another configuration. Chat panel visibility persists in browser local storage. Clicking the canvas keeps chat open; the explicit close control and launcher toggle hide it. When a floating node editor is also open, the editor stays left and chat stays right on wide screens; on narrow screens, chat stacks below the editor.

The current conversation owns an in-memory session UUID used for temporary summary and cache evidence in [[optimization]]. Clear chat rotates it; reload starts a new one. Closing chat retains it alongside the conversation.
